# .NET Developer — Clean Architecture

`[Activated: .NET Developer]`

Strict Clean Architecture: Domain → Application → Infrastructure → Api. `Result<T>` for all returns. `[Injectable]` for DI auto-registration. Static mappers + LINQ projections.

> **Absolute rule**: all methods return `Task<Result<T>>` or `Task<Result>` · never an uncaught exception outside the `SafeExecute` pattern · `[Injectable]` on all services/repositories · mappers as separate static classes · LINQ projections as `Expression<Func<>>` to avoid materialization · `DbEntity` suffix on EF entities · `DbEnum` suffix on enums · XML comments on all public members.

## ✓ Validators — FluentValidation on RequestDTOs

Validation lives **at the edge of the request**. `AbstractValidator<TRequestDto>` for each DTO.

- **Mandatory location**:
  - `src/Application/DTOs/Requests/*Validator.cs` (one per RequestDto)
- **Critical elements**:
  - Basic validations (NotEmpty, MaxLength, IsEnum, Range)
  - FK validations (MustAsync + repository check)
  - Custom validations (complex business logic)
  - Localized messages
- **Registration**: `services.AddValidatorsFromAssemblies(...)` in DI
- **Automatic**: `[ApiController]` validates automatically → 400 + detailed errors on failure
- **Full example** → see the `dto-architect` skill (CreateDemandeRequestDtoValidator)

## 📊 Projections — LINQ Expression DbEntity → ResponseDto

Projections convert **at the SQL level** for performance (no full entity loading).

- **Mandatory location**:
  - `src/Application/Mappers/*Mapper.cs` (static class with `Expression<Func<TDbEntity, TResponseDto>>`)
- **Critical elements**:
  - `Expression<Func<>>` projection for SQL-level Select()
  - `.ToString()` enums in the projection
  - **Never** include raw navigations (FK relations)
  - Minimal columns only
  - `.Compile()` for in-memory execution if needed
- **Usage**: `.Select(Mapper.ToDtoProjection).ToListAsync()` in the repository
- **In-memory alternative**: map after Include() if navigations are required
- **Full example** → see the `dto-architect` skill (DemandeMapper.ToDtoProjection)

Services orchestrate business logic: **validated RequestDto → Repository → Transformations → ResponseDto**. Never business logic in the controller or the repository.

### Service implementation

```csharp
// Application/Services/DemandeService.cs
[Injectable]
public class DemandeService : IDemandeService
{
    // ──── Injections ────
    private readonly IUnitOfWork _unitOfWork;
    private readonly IEmailService _emailService;
    private readonly ICurrentUserService _currentUserService;
    private readonly ISophiaService _sophiaService;
    private readonly IDemandeBusinessRuleService _br;
    private readonly ITemplateRenderService _templateRender;
    private readonly IPdfService _pdfService;
    
    public DemandeService(
        ILogger<DemandeService> logger,
        ICurrentRequestService currentRequest,
        IUnitOfWork unitOfWork,
        IEmailService emailService,
        ICurrentUserService currentUserService,
        ISophiaService sophiaService,
        IDemandeBusinessRuleService br,
        ITemplateRenderService templateRender,
        IPdfService pdfService)
        : base(logger, unitOfWork.DemandeRepository)
    {
        _unitOfWork = unitOfWork;
        _emailService = emailService;
        _currentUserService = currentUserService;
        _sophiaService = sophiaService;
        _br = br;
        _templateRender = templateRender;
        _pdfService = pdfService;
    }
    
    /// <summary>
    /// CREATE — Validate → Map → Persist → Enqueue → Return
    /// </summary>
    public Task<Result<DemandeReadDto>> CreateDemande(DemandeWriteDto dto) =>
        Result<DemandeReadDto>.SafeExecute(async () =>
        {
            var entity = DemandeMappers.MapToDbEntity(dto, _currentUserService.ZoneId);
            var created = await _unitOfWork.DemandeRepository.Create(entity)
                .ThrowIfNotSuccess();
            
            await _demandeCreatedQueue.EnqueueAsync(created.Id);
            
            return await GetDemande(created.Id);
        });
    
    /// <summary>
    /// ASSIGN — Atomic locking + Idempotence
    /// </summary>
    public Task<Result<DemandeReadDto>> AssignDemande(Guid id) =>
        Result<DemandeReadDto>.SafeExecute(async () =>
        {
            await _unitOfWork.DemandeRepository
                .AcquireDemande(id, _currentUserService.UserId)
                .ThrowIfNotSuccess();
            
            return await GetDemande(id);
        });
    
    /// <summary>
    /// UPDATE — Validate state → Apply → Trace → Optional enqueue
    /// </summary>
    public Task<Result<DemandeReadDto>> UpdateDemande(Guid id, DemandeWriteDto dto) =>
        Result<DemandeReadDto>.SafeExecute(async () =>
        {
            var entity = await _unitOfWork.DemandeRepository.FindById(id)
                .ThrowIfNotSuccess();
            
            _br.EnsureDemandeCanBeUpdated(entity).ThrowIfNotSuccess();
            
            DemandeMappers.ApplyToDbEntity(dto, entity);
            
            await _unitOfWork.DemandeHistoryRepository.Add(
                new DemandeHistoryDbEntity { 
                    Action = DemandeHistoryActionDbEnum.Updated, 
                    DemandeId = id 
                });
            
            await _unitOfWork.DemandeRepository.UpdateAndSave(entity)
                .ThrowIfNotSuccess();
            
            if (dto.IsUrgent)
                await _demandeCreatedQueue.EnqueueAsync(id);
            
            return await GetDemande(id);
        });
    
    /// <summary>
    /// ORCHESTRATE AI — Call Sophia → Persist → Enqueue next
    /// </summary>
    public Task<Result> SetGeneratedIAContent(Guid id, CancellationToken ct = default) =>
        Result.SafeExecute(async () =>
        {
            var entity = await _unitOfWork.DemandeRepository
                .FindDemandeWithIaDetails(id).ThrowIfNotSuccess();
            
            var iaResult = await _sophiaService.GenerateSummaryAsync(entity, ct)
                .ThrowIfNotSuccess();
            
            entity.Summary.Content = iaResult.Content;
            entity.Summary.Status = DemandeGenerationStatusDbEnum.Done;
            
            await _unitOfWork.DemandeRepository.UpdateAndSave(entity)
                .ThrowIfNotSuccess();
            
            if (entity.IsUrgent)
                await _demandeIaQueue.EnqueueAsync(id);
            
            return Result.Success;
        });
    
    private Task<Result<DemandeReadDto>> GetDemande(Guid id) =>
        GetEntityById(id, DemandeProjections.ProjectToDemandeReadDto);
}
```

### Controller — calls the service, never the repository directly

```csharp
[ApiController]
[Route("api/[controller]")]
public class DemandeController
{
    public DemandeController(private IDemandeService _service) {}
    
    [HttpPost]
    public async Task<IActionResult> Create([FromBody] DemandeWriteDto dto)
    {
        // Service handles: validation (DTO), persistence, queue, return DTO
        var result = await _service.CreateDemande(dto);
        return result.IsSuccess ? CreatedAtAction(nameof(Get), new { id = result.Data.Id }, result.Data)
            : BadRequest(result.GetError());
    }
}
```

**Key patterns**:
- **Result<T>** wrapper — success/error monad
- **SafeExecute** — automatic catch-all
- **UnitOfWork.ThrowIfNotSuccess()** — short-circuit on error
- **Atomic transactions** (via UnitOfWork.SaveChangesAsync)
- Idempotence — check state before acting
- History tracking — every mutation recorded
- **[Injectable]** — auto-registration DI
- **Service receives interface injection**, never a direct DbContext implementation

### Where does business logic live?

| Logic | Lives in | Never in |
|---------|----------|-------------|
| Basic validations (NotEmpty, MaxLength, IsEnum) | **FluentValidation** | ❌ Service |
| Complex rules (state machine, dependencies) | **BusinessRuleService** or Aggregate | ❌ Controller |
| Entity ↔ DTO transformation | **Mapper** (static class) | ❌ Service |
| Persistence access | **Repository** (interface) | ❌ Direct service (DbContext) |
| Orchestration (service calls + persistence) | **Service** (here) | ✅ Correct |
| Multi-step transactions | **Service** (UnitOfWork) | ❌ Repository |
| Domain business behavior | **Aggregate root** | ❌ Raw service |

## 🔄 Mappers — Entity ↔ DTO conversion

Static mappers convert at the right time (SQL-level or in memory).

- **Mandatory location**:
  - `src/Application/Mappers/*Mapper.cs` (static class)
- **Critical elements**:
  - LINQ projections for SQL-level conversions (repository)
  - In-memory mappers when navigations/relations are needed
  - Bidirectional: Entity → DTO, RequestDto → Entity
  - Enums: string ↔ enum conversion
  - Null-safety: check nullability before converting
- **Full example** → see the `dto-architect` skill (DemandeMapper with ToDtoProjection + ToDetailDto + FromRequestDto)

## 📦 Repositories — Persistence abstraction

Repositories **abstract data access** — services call the repository, never the DbContext. Interface + implementation pattern.

### Full .NET structure

- **Mandatory location**:
  - `src/Shared/Application/IBaseServiceRepository.cs` (base CRUD interface)
  - `src/<Domain>/Application/I<Entity>Repository.cs` (specialized business interface)
  - `src/<Domain>/Infrastructure/Repositories/<Entity>Repository.cs` (`[Injectable]` implementation)
- **Hierarchy**:
  - `IBaseServiceRepository<TEntity>` (CRUD: Get, Find, GetCount, Create, Update, Delete, etc.)
  - `I<Entity>Repository : IBaseServiceRepository<TEntity>` (specialized business queries)
  - `<Entity>Repository : PostGresRepository<TContext, TEntity>, I<Entity>Repository` (implementation)
- **Required**:
  - Atomic transactions (`BeginTransactionAsync`) for multi-updates
  - Eager loading via `.Include()` (no N+1)
  - Bulk updates `.ExecuteUpdateAsync()` for performance
  - `Expression<Func<>>` projections for Entity → DTO at the DB level
  - Idempotence on sensitive queries (acquire, assign, supervise)
  - `Result<T>` pattern for error handling
  - `[Injectable]` on the implementation class
- **Service calls repository**: never DbContext directly
- **Full example** → see the `dto-architect` skill (IBaseServiceRepository + IDemandeRepository + DemandeRepository)

## ⚙️ EF Core Configuration — Constraints & Performance

**Mandatory**: every DbEntity has its `IEntityTypeConfiguration<T>` class defining indices, lengths, conversions, relations, cascade delete. This guarantees migrations create the right structure **and** the right DB constraints.

- **Mandatory location**:
  - `src/Infrastructure/Persistence/Configurations/` → `*Configuration.cs` (one per DbEntity)
  - Applied in `DbContext.OnModelCreating()` via `modelBuilder.ApplyConfiguration(new ...())`
- **Critical elements**:
  - **Indices**: Status, Category, CreatedDate, foreign keys (filter/sort performance)
  - **MaxLength**: all string fields (integrity + perf)
  - **Enum conversion**: `<int>` (serialize as int in DB, not string)
  - **Default values**: in DB, not in the app (DemandeCategoryDbEnum.None)
  - **Collation**: if specific text search/sorting is needed
  - **Relationships**: HasOne/WithMany/HasForeignKey + cascade delete on required one-to-one
  - **Ignore**: unmapped computed properties (AllDemandeLinks)
- **Full example** → see the `dto-architect` skill (DemandeConfiguration)
- **Migration**: `dotnet ef migrations add CreateDemande` generates SQL **with indices and constraints** if the configuration is correct.
- **Verification**: re-read the generated `.sql` file, check indices and defaults before pushing.

## ⚡ Performance — backend checklist to check on EVERY deliverable

N+1, SQL-level projections, and indexes are already covered above (Projections, Repositories,
EF Core Configuration sections). The following points are not covered yet:

- [ ] **Async jobs**: every slow operation (mail, export, PDF, AI call) runs through a background
  service/queue (`EnqueueAsync`, already shown in Services above) — never synchronously inside
  the controller action.
- [ ] **Compression**: `ResponseCompressionMiddleware` (Brotli + gzip) enabled in `Program.cs`.
  Without it, every JSON response weighs 2 to 4 times more to transfer.
- [ ] **AI streaming**: every long AI generation response streams (`IAsyncEnumerable<T>` or
  Server-Sent Events), instead of returning as one block after full generation — otherwise the
  user waits for the whole text before seeing the first letter.
- [ ] **Pagination**: every list endpoint returns `PaginatedData<T>` (already shown in Phase 8,
  `GetFeatures()`) — never an unbounded `.ToListAsync()` on a table that can grow.
- [ ] **Cache on hot data**: anything read often and changed rarely (reference data,
  configuration) goes through `IMemoryCache`/Redis with an explicit TTL — not a repeated EF Core
  query for stable data.

> Connection pooling, external API timeouts, retry/backoff, rate limiting, and graceful
> degradation are already covered by the **Resilience under load** checklist in the global
> `AGENTS.md` — do not duplicate it here. The carbon angle of these same optimizations is in
> `skills/green-it/SKILL.md` Phase 3 — refer to it instead of restating it.

## 🗂️ DbEntity — Infrastructure layer (persistence)

`DbEntity`s are **internal to the Infrastructure layer**. Never in an API response. Shared interfaces (`IHasDateTime`, `IHasAuditUser`, `IDeadLine`, etc.) avoid duplication.

- **Mandatory structure**:
  - `src/Infrastructure/Persistence/Entities/` → `*DbEntity.cs` (EF Core aware, **mandatory** suffix)
  - `src/Infrastructure/Persistence/Interfaces/` → `IHasDateTime.cs`, `IHasAuditUser.cs`, etc. (shared across entities)
  - `src/Infrastructure/Persistence/Configurations/` → `*DbEntityConfiguration.cs` (Fluent API)
- **Minimal rules**:
  - Mandatory inheritance from a `KeyDbEntity` base (`public Guid Id`).
  - **Strict** `DbEntity` suffix (never `Entity`, never `Model`).
  - Shared properties via interfaces: `IHasDateTime`, `IHasAuditUser`, `ICode`, `IDeadLine`, `IAssignation`, `ISupervision`, etc.
  - Collections: `ICollection<T> = []`, never a List that publicly exposes `Add()`.
  - Navigations: `public virtual AddressDbEntity Address { get; set; }`, documented with `/// <summary>`.
  - **No business logic** in the DbEntity — it's a pure ORM container.
  - Enums: `DbEnum` suffix (e.g. `DemandeStatusDbEnum`, distinct from business enums).
  - Null-safety: `public string Title { get; set; } = string.Empty;`.
- **Full detail (interfaces, DemandeDbEntity example, structure)** → see the `dto-architect` skill.

## 📦 DTOs — delegated to `dto-architect`

Every public API method returns a `Result<T>` where **T is a DTO or a primitive type**, never a `*DbEntity`.

- **Mandatory location**:
  - `src/Application/DTOs/Requests/` → `Create<Feature>RequestDto.cs` + `Create<Feature>RequestDtoValidator.cs` (FluentValidation)
  - `src/Application/DTOs/Responses/` → `<Feature>ResponseDto.cs`
  - `src/Application/Mappers/` → `<Feature>Mapper.cs` (static class + `Expression<Func<TDbEntity, TResponseDto>> ToDtoProjection`)
- **Minimal rules**:
  - Strict `RequestDto` / `ResponseDto` suffix (never `UserDto`)
  - Immutable C# `record`s — no mutable classes
  - Validation via `AbstractValidator<TRequestDto>` in the same folder as the DTO
  - LINQ projection (`Select(UserMapper.ToDtoProjection)`) on every EF Core query that returns a DTO — never `.ToList()` then in-memory mapping
  - **`Ok(userDbEntity)` FORBIDDEN** — must call `UserMapper.ToDto()`. A DbEntity never goes into JSON.
  - Never include raw navigations in a DTO (e.g. `Source`, `Address`, `Requester`) — use IDs or explicit nested DTOs.
  - Sensitive fields never in a `ResponseDto` (password hash, refresh token, internal data)
- **When to create a DTO**: every minimal API/controller endpoint, every CQRS Command/Query, every MediatR handler.
- **Full detail (mapping, versioning, advanced projections)** → see the `dto-architect` skill.

### Phase 4 — EF Core Configuration

> ⚠️ **Configuration rule**: one class per entity in `Infrastructure/Database/Configurations/` · Fluent API exclusively (no DataAnnotations) · index on filtered columns · `search_ci_ai` collation on searchable text fields · `HasConversion<int>()` on enums
>
> ⚠️ **Data isolation (`security-architect`, table-by-table discipline)**: any entity
> carrying an ownership column (`ZoneId`, `TenantId`, `UserId`...) declares a global **Query Filter**
> in its configuration — never a `.Where()` manually added to each repository query, which
> gets forgotten on the first ad hoc query. `builder.HasQueryFilter(e =>
> e.ZoneId == _currentZoneId)` (`ICurrentZoneAccessor` service injected into the
> configuration class). Full reference: `skills/security-architect/SKILL.md`, "Row-level
> data isolation" section.

```csharp
using Microsoft.EntityFrameworkCore;
using Microsoft.EntityFrameworkCore.Metadata.Builders;
using MonOrg.Backend.[Service].Domain.DbEntities;
using MonOrg.Backend.Shared.Infrastructure.Database;

namespace MonOrg.Backend.[Service].Infrastructure.Database.Configurations;

internal class [Feature]Configuration : IEntityTypeConfiguration<[Feature]DbEntity>
{
    public void Configure(EntityTypeBuilder<[Feature]DbEntity> builder)
    {
        // Indexes
        builder.HasIndex(p => p.Status);
        builder.HasIndex(p => p.ZoneId);
        builder.HasIndex(p => p.CreatedDate);

        // Enum → int storage
        builder.Property(p => p.Status)
            .HasConversion<int>()
            .HasDefaultValue([Feature]StatusDbEnum.Pending);

        // Text columns — collation for CI/AI search
        builder.Property(x => x.Title)
            .HasMaxLength(LengthTextConfig.TitleTextString)
            .UseCollation(DemandeDbContext.CollationName);

        builder.Property(x => x.Description)
            .HasColumnType("text")
            .HasMaxLength(LengthTextConfig.BigTextString);

        // Relationships
        builder.HasMany(x => x.Histories)
            .WithOne(h => h.[Feature])
            .HasForeignKey(h => h.[Feature]Id)
            .OnDelete(DeleteBehavior.Cascade);
    }
}
```

### Phase 5 — Mapper + Projection

> ⚠️ **Mapper rule**: static classes · `Func<WriteDto, DbEntity>` for creation (factory pattern) · separate `Apply(WriteDto, DbEntity)` method for updates · **never** AutoMapper

> ⚠️ **Projection rule**: `Expression<Func<DbEntity, ReadDto>>` compiled into the LINQ query · never `.ToList()` before `.Select()` · include only the fields needed by the DTO

```csharp

// ReadDto and WriteDto are auto-generated from OpenAPI — adapt the import

public static class [Feature]Mappers
{

        dto => new [Feature]DbEntity
        {
            Title = dto.Title,
            Description = dto.Description,
            Status = [Feature]StatusDbEnum.Pending,

        [Feature]WriteDto dto,

        entity.Title = dto.Title;
        entity.Description = dto.Description;
```

```csharp
using System.Linq.Expressions;
using MonOrg.Backend.[Service].Domain.DbEntities;
// ReadDto auto-generated — adapt the import

namespace MonOrg.Backend.[Service].Application.Projections;

/// <summary>LINQ projections for [Feature] — compiled into SQL by EF Core.</summary>
public static class [Feature]Projections
{
    /// <summary>Full read projection for detail views.</summary>
    public static Expression<Func<[Feature]DbEntity, [Feature]ReadDto>> ProjectTo[Feature]ReadDto =>
```

### Phase 7 — Repository

> ⚠️ **Repository rule**: inherit `PostGresRepository<TContext, TDbEntity>` · `[Injectable]` mandatory · explicit transactions for multi-step operations · `ExecuteUpdateAsync` for bulk updates (not `SaveChanges` per item)

```csharp
using Microsoft.EntityFrameworkCore;
using MonOrg.Backend.[Service].Application.Infrastructure.Repositories;
using MonOrg.Backend.[Service].Domain.DbEntities;
using MonOrg.Backend.[Service].Infrastructure.Database.Contexts;
using MonOrg.Backend.Shared.App;
using MonOrg.Backend.Shared.Infrastructure.Repositories;
using MonOrg.Backend.Shared.Patterns.Result;

namespace MonOrg.Backend.[Service].Infrastructure.Repositories;

/// <summary>Repository for [Feature] entities.</summary>
[Injectable]
public class [Feature]Repository(
    [Service]DbContext context
) : PostGresRepository<[Service]DbContext, [Feature]DbEntity>,
    I[Feature]Repository
{
    /// <summary>Acquire [feature] atomically — prevents double assignment.</summary>
    public async Task<Result> Acquire[Feature](Guid featureId, Guid userId)
    {
        await using var transaction = await Context.Database.BeginTransactionAsync();

        var updated = await DbSet
            .Where(f => f.Id == featureId && f.AssignedUserId == null)
            .ExecuteUpdateAsync(setter => setter
                .SetProperty(p => p.AssignedUserId, userId)
                .SetProperty(p => p.AssignedDate, DateTime.UtcNow));

        if (updated == 1)
        {
            Context.Set<[Feature]HistoryDbEntity>().Add(new [Feature]HistoryDbEntity
            {
                [Feature]Id = featureId,
                Action = [Feature]HistoryActionDbEnum.Acquired,
                UserId = userId,
            });

            await Context.SaveChangesAsync();
            await transaction.CommitAsync();

            return Result.Success;
        }

        if (await DbSet.AnyAsync(f => f.Id == featureId && f.AssignedUserId == userId))
            return Result.Success;

        return Result.Already.WithReason("Already acquired by another user");
    }
}
```
