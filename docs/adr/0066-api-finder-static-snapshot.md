# ADR 0066 — api-finder: a static snapshot rather than a runtime clone

**Date:** 2026-10-02
**Status:** Accepted

## Decision

The `api-finder` skill ships a frozen excerpt of
[bocal-pol/public-apis](https://github.com/bocal-pol/public-apis) at
`skills/api-finder/references/public-apis.md`, rather than cloning or querying the repo on
every invocation.

## Reason

The source file (README.md, ~280KB, 2,478 lines) fits entirely into a tier-3 resource (loaded on
demand, never at skill trigger time) once stripped of promotional noise (vendor banners, affiliate
buttons). Cloning or making a network call on every invocation adds a dependency and latency for
content that doesn't change from one invocation to the next within the same working session.

## Consequences

- The catalog goes stale silently: a new category or API added to the source repo after 2026-10-02
  won't appear until the snapshot is regenerated by hand.
- `SKILL.md` explicitly warns to check the source repo if a category looks thin for a given need,
  rather than concluding no matching API exists.
- No automatic refresh mechanism at this stage: worth reconsidering if the catalog proves stale in
  real use (switching then to a one-off fetch or a cached clone under `~/.claude/`, rejected here as
  a first solution for a need not yet proven).

## Alternatives considered

- **A shallow clone cached under `~/.claude/`, refreshed if older than 7 days**: adds cache
  management and a network dependency for a marginal gain until real usage shows freshness is an
  actual problem.
- **A live fetch on every invocation**: systematic latency and network dependency, for content that
  changes on a monthly scale, not a per-session one.
